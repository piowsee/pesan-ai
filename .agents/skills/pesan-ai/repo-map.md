# Repository Map

This file is a high-level map of the repo. It is for orientation, not feature-by-feature documentation.

## Stack Snapshot

- Next.js 16 App Router
- React 19
- TypeScript with `strict: true`
- Tailwind CSS v4 with shadcn `radix-nova`
- TanStack Query for client data
- Better Auth for auth and onboarding
- Prisma + PostgreSQL
- `next-intl` for localized public pages
- Vitest for route, service, and repository tests

## Top-Level App Shape

- `src/app/[locale]`: public landing, auth, and legal pages.
- `src/app/(user-page)/dashboard`: authenticated operator area.
- `src/app/(admin-page)/admin`: authenticated admin area.
- `src/app/api`: backend route handlers.
- `src/components/ui`: shared design-system primitives.
- `src/components/*`: feature-oriented UI grouped by domain.
- `src/hooks`: feature-owned client hooks, including TanStack Query hooks and workflow hooks.
- `src/services`: business rules and orchestration.
- `src/repositories`: Prisma queries and transactions.
- `src/schemas`: Zod request and webhook payload validation.
- `src/lib/api-helper`: route-layer and HTTP helpers.
- `src/lib/chat`: chat-domain helpers and realtime bus helpers.
- `src/lib/i18n-helper`: locale and localized metadata helpers.
- `src/lib/server`: server-only infrastructure.
- `src/lib/auth`: auth helpers and better-auth setup.
- `src/lib/utils.ts`: shared UI utility helpers like `cn(...)`.

## Auth, Routing, and Locale Rules

- `src/proxy.ts` is the request gatekeeper.
- Public pages use `next-intl` locale prefixes via `src/i18n/*`.
- `/dashboard` and `/admin` are protected by better-auth session cookies.
- Login is locale-aware and handled under `src/app/[locale]/(auth-page)`.
- API routes use `AuthHelper`.
- Protected page layouts use `AuthPageHelper`.
- Dashboard and admin pages are currently not locale-prefixed in their internal links, so do not blindly add locale wrappers to protected flows.

## Shared Runtime Context

- Root layout mounts `QueryProvider`, `RealtimeProvider`, `TooltipProvider`, and `Toaster`.
- Dashboard layout mounts `AppSidebar` and `MobileBottomNav`.
- `RealtimeProvider` owns the long-lived SSE connection and shared realtime cache updates.

## Database Source of Truth

- Schema: `prisma/schema.prisma`
- Migrations: `prisma/migrations/*`
- Seed script: `prisma/seed.ts`
- Generated Prisma client: `src/generated/prisma`

Do not edit generated Prisma files manually. Change the schema, then regenerate.

## Local Architecture Pattern

- Route handlers stay thin and use `src/lib/api-helper`.
- Services own orchestration, business rules, provider calls, and cross-repository flows.
- Repositories own Prisma queries and transactions.
- Shared server-only concerns belong in `src/lib/server`.
- Domain-specific helpers belong in domain folders like `src/lib/chat`.

## Useful Shared Helpers

- `src/lib/api-helper/api-handler.ts`: auth wrappers and centralized API error mapping
- `src/lib/api-helper/jsend.ts`: standard success/fail/error response format
- `src/lib/api-helper/error.ts`: `ApiError` and client-side error extraction
- `src/lib/api-helper/pagination.ts`: shared `page` and `limit` parsing
- `src/lib/server/fetch-with-retry.ts`: retry wrapper for Meta API calls
- `src/lib/server/prisma.ts`: singleton Prisma client
- `src/lib/server/logger.ts`: structured logging helpers
- `src/lib/server/encryption.ts`: encryption and decryption helpers
- `src/lib/chat/chat.ts`: freeform window and chat helper utilities
- `src/lib/chat/chat-format.ts`: chat-specific timestamp and last-seen formatting
- `src/lib/chat/event-bus.ts`: in-memory realtime bus
- `src/lib/i18n-helper/locale.ts`: locale inference and locale type helpers
- `src/lib/i18n-helper/seo.ts`: localized metadata builder

When moving or adding helpers, keep the same intent:

- `api-helper` for HTTP/API concerns
- `chat` for chat-domain helpers
- `i18n-helper` for locale/metadata helpers
- `server` for server-only infrastructure

Avoid turning `src/lib` back into a generic dump folder.

## Core Data Model

- The main domain shape is user-owned business accounts, account-linked phone numbers, conversations, and messages.
- This project tracks both internal database IDs and provider-facing IDs. Verify which one a flow expects before wiring a route or mutation.
- Unread and realtime behavior are part of the domain, not just UI details.

## Generated and Seeded Test Context

- `prisma/seed.ts` creates baseline admin, regular user, WABA, webhook, phone number, conversation, and messages.
- `tests/seed-data.ts` is generated by the seed script and is the canonical source for seeded IDs used in repository tests.

If you change seed assumptions, keep the seed script and repository tests aligned.
